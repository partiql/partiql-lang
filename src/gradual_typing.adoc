[[sec:gradual-typing]]
== Gradual Typing

PartiQL supports _gradual typing_, which allows data to range from completely untyped (schema-less) to fully typed with structural types (schemas). This flexibility enables PartiQL to work effectively with both traditional relational databases with rigid schemas and modern semi-structured data stores without predefined schemas.

The gradual typing system provides several key benefits:

* *Schema Optional*: Queries can execute successfully with or without schema information
* *Schema Beneficial*: When schemas are available, they enable compile-time error detection, query optimization, and better tooling support
* *Stability*: Query results remain stable when schemas are added or modified, maintaining consistent behavior

[[sec:schema-validation]]
=== Schema Validation

When structural types (schemas) are available, PartiQL can leverage them for validation and optimization. Schema validation in PartiQL:

* *Compile-time Error Detection*: When schema information indicates that a path expression will always return `MISSING` (e.g., referencing a non-existent attribute in a table), the query processor may throw a compile-time error. The extent of error detection is implementation-specific.

* *Type Compatibility Checking*: Schemas enable the query processor to verify type compatibility at compile time. For example, if a schema indicates that an attribute is always numeric, the processor can validate that operations on that attribute are type-appropriate.

* *SQL Compatibility*: In the presence of schema validation that matches SQL's rigid schemas, PartiQL behaves identically to SQL. For instance, referring to a non-existent column in a SQL table will produce a compilation error, just as it does in SQL.

* *Optimization Opportunities*: Schema information enables query optimizers to make better decisions about query execution plans, index usage, and data access patterns.

Schema validation is optional and its availability depends on:

1. Whether the data source provides schema information
2. Whether the query explicitly references schema information
3. The implementation's capabilities for schema inference and validation

[[sec:type-inference]]
=== Type Inference

PartiQL implementations may employ type inference to derive type information even in the absence of explicit schemas. Type inference enables:

* *Partial Type Knowledge*: Even without complete schemas, the query processor can infer types from query structure, literal values, and function signatures
* *Progressive Refinement*: Type information can be progressively refined as more context becomes available during query compilation and execution
* *Error Prevention*: Inferred types can help catch certain classes of errors earlier in the query processing pipeline

Type inference in PartiQL is conservative: when type information cannot be reliably inferred, the system defaults to treating values as having union types (capable of being any PartiQL type), maintaining the permissive behavior expected for schema-less data.
