[[sec:collection-types]]
=== Collection Types

PartiQL supports two fundamental collection types: arrays (ordered) and bags (unordered). Both can contain elements of any PartiQL type and allow duplicates.

[[sec:arrays]]
==== Arrays

Arrays are ordered collections where elements are accessible by zero-based index.

[cols="1,1,3", options="header"]
|===
|Type |Bit Size |Description

|`ARRAY`
|Variable
|Ordered, indexed collection allowing duplicates
|===

*EBNF Syntax for Array Constructors:*
[source, ebnf]
----
array_value = "[", [ value, { ",", value } ], "]" ;
----

*Characteristics:*
- *Ordered*: Element order is significant and preserved
- *Indexed*: Elements accessible by zero-based integer index
- *Size*: Has explicit size (number of elements)
- *Duplicates*: Multiple elements with same value allowed
- *Heterogeneous*: Elements can have different types

*Storage:* Variable size depending on:
- Number of elements
- Types and sizes of element values
- Indexing metadata

*Examples:*
[source, partiql]
----
[]                                    -- empty array
[1, 2, 3, 4, 5]                      -- array of integers
['a', 'b', 'c']                      -- array of strings
[1, 'two', 3.0, true]                -- heterogeneous array
[[1, 2], [3, 4]]                     -- nested arrays
[{'a': 1}, {'b': 2}]                 -- array of tuples
----

*Array Access:*
[source, partiql]
----
[1, 2, 3][0]                         -- Returns: 1
[1, 2, 3][2]                         -- Returns: 3
[1, 2, 3][10]                        -- Returns: MISSING (out of bounds)
----

[[sec:bags]]
==== Bags

Bags are unordered collections where elements are not accessible by position.

[cols="1,1,3", options="header"]
|===
|Type |Bit Size |Description

|`BAG`
|Variable
|Unordered collection allowing duplicates
|===

*EBNF Syntax for Bag Constructors:*
[source, ebnf]
----
bag_value = "<<", [ value, { ",", value } ], ">>" ;
----

*Characteristics:*
- *Unordered*: Element order is not significant
- *No Indexing*: Elements not accessible by position
- *Duplicates*: Multiple elements with same value allowed  
- *Heterogeneous*: Elements can have different types
- *SQL Compatibility*: SQL tables are bags of tuples

*Storage:* Variable size depending on:
- Number of elements
- Types and sizes of element values
- No ordering metadata needed

*Examples:*
[source, partiql]
----
<<>>                                 -- empty bag
<<1, 2, 3, 2, 1>>                    -- bag with duplicates
<<'a', 'b', 'c'>>                    -- bag of strings
<<1, 'two', 3.0, true>>              -- heterogeneous bag
<<{'a': 1}, {'b': 2}>>               -- bag of tuples (like SQL table)
----

*Bag Equality:*
[source, partiql]
----
<<1, 2, 3>> = <<3, 2, 1>>            -- TRUE (order doesn't matter)
<<1, 2, 2>> = <<1, 2>>               -- FALSE (duplicates count)
<<1, 2, 3>> = [1, 2, 3]              -- FALSE (different types)
----
