[[sec:tuple-struct-types]]
=== Tuple/Struct Types

Tuples (also called structs) are unordered or ordered collections of attribute-value pairs, where each attribute has a name (string) and an associated value of any PartiQL type.

[cols="1,1,3", options="header"]
|===
|Type |Bit Size |Description

|`STRUCT` / `TUPLE`
|Variable
|Collection of named attribute-value pairs
|===

*EBNF Syntax for Tuple Constructors:*
[source, ebnf]
----
tuple_value = "{", [ attribute_pair, { ",", attribute_pair } ], "}" ;

attribute_pair = attribute_name, ":", value ;

attribute_name = string_literal 
               | identifier 
               | "(" expression ")" ;

identifier = letter, { letter | digit | "_" | "$" }
           | '"', quoted_identifier_body, '"' ;
----

*Storage:* Variable size depending on:

* Number of attributes
* Names of attributes (string length)
* Types and values of attribute values
* Ordering information (if ordered tuple)

*Examples:*
[source, partiql]
----
{}                                    -- empty tuple
{'a': 1, 'b': 2}                     -- simple tuple
{'name': 'John', 'age': 30, 'active': true}
{'nested': {'x': 1, 'y': 2}}         -- nested tuple
----

[[sec:ordered-vs-unordered-tuples]]
==== Ordered vs. Unordered Tuples

PartiQL distinguishes between ordered and unordered tuples, though the distinction is typically determined by type definitions rather than syntax.

*Unordered Tuples:*

* Default behavior in dynamically typed contexts
* Attribute order is not significant
* `{'a': 1, 'b': 2}` equals `{'b': 2, 'a': 1}`
* Attribute access by name only

*Ordered Tuples:*

* Specified by type definitions
* Attribute order is significant and preserved
* Positional access may be available (implementation-defined)
* SQL tables with defined column order produce ordered tuples
* Attribute order affects iteration and certain operations

*Schema Declaration:*
[source, sql]
----
-- Ordered tuple (via SQL table definition)
CREATE TABLE users (
    id INT,
    name VARCHAR(100),
    email VARCHAR(255)
)

-- Results in ordered tuples: {'id': _, 'name': _, 'email': _}
----

[[sec:attribute-names-and-values]]
==== Attribute Names and Values

*Attribute Names:*

* Must be strings (any Unicode string)
* Can be identifiers or quoted strings
* Can be computed dynamically using expressions
* Case-sensitive by default (implementation may vary)

*Attribute Values:*

* Can be any PartiQL type (scalars, collections, tuples)
* Can be NULL (but not MISSING - see special handling below)
* Fully heterogeneous: different tuples can have different value types for same attribute name

*MISSING Attributes:*
When constructing tuples, if an attribute value evaluates to `MISSING`, the attribute is omitted entirely from the tuple rather than being included with a MISSING value.

*Examples:*
[source, partiql]
----
-- Dynamic attribute names
{('prefix_' || 'name'): 'value'}      -- {'prefix_name': 'value'}

-- Heterogeneous values
{'x': 1}                               -- x is integer
{'x': 'hello'}                         -- x is string (different tuple)

-- MISSING handling
{'a': 1, 'b': MISSING}                 -- Results in: {'a': 1}
----

[[sec:duplicate-attribute-names]]
==== Duplicate Attribute Names

PartiQL allows duplicate attribute names within tuples for compatibility with non-strict JSON/Ion datasets, though this is not encouraged.

*Behavior with Duplicates:*

* Tuples may contain multiple attributes with the same name
* Path navigation `t.attr` returns the *first* occurrence (for ordered tuples) or an implementation-defined occurrence (for unordered tuples)
* Deep equality compares all attributes, including duplicates
* `UNPIVOT` can access all occurrences

*Ordered Tuples:* First occurrence is well-defined based on order defined by type definitions.

*Unordered Tuples:* First occurrence is implementation-defined in permissive mode, error in type-checking mode.

*Examples:*
[source, partiql]
----
{'a': 1, 'a': 2}                      -- Tuple with duplicate 'a'
{'a': 1, 'a': 2}.a                    -- Returns 1 (first occurrence)

-- Access all values using UNPIVOT
SELECT VALUE v
FROM UNPIVOT {'a': 1, 'a': 2, 'b': 3} AS v AT attr
WHERE attr = 'a'
-- Returns: <<1, 2>>
----
