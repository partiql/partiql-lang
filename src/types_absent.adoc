[[sec:absent-values]]
=== Absent Values (NULL and MISSING)

PartiQL has two kinds of absent values to distinguish between null-valued data and missing data, enabling better handling of semi-structured data.

[cols="1,1,3", options="header"]
|===
|Type |Bit Size |Description

|`NULL`
|Implementation-defined (typically 1 bit + tag)
|Explicit null value (SQL null)

|`MISSING`
|Implementation-defined (typically 1 bit + tag)
|Absent/undefined value (not present in data)
|===

*EBNF Syntax:*
[source, ebnf]
----
absent_value = "NULL" | "null" | "MISSING" ;
----

==== NULL

`NULL` represents an explicit null value, compatible with SQL's NULL semantics.

*Characteristics:*
- Explicit presence of unknown/inapplicable value
- Can be stored as attribute value in tuples
- Participates in SQL three-valued logic
- `NULL = NULL` is not TRUE (returns NULL in SQL semantics)

*Examples:*
[source, partiql]
----
{'a': 1, 'b': NULL}                  -- tuple with explicit NULL
[1, NULL, 3]                         -- array with NULL element
NULL + 5                             -- Returns: NULL
NULL > 0                             -- Returns: NULL (or false in boolean context)
----

==== MISSING

`MISSING` represents the absence of data, typical in semi-structured data where attributes may not exist.

*Characteristics:*
- Indicates data is not present
- *Cannot* be stored as attribute value in tuples (omitted instead)
- Can appear in arrays and bags
- Path navigation to non-existent attribute returns MISSING
- Operations on MISSING typically return MISSING

*Examples:*
[source, partiql]
----
{'a': 1}.b                           -- Returns: MISSING
[1, MISSING, 3]                      -- Array with MISSING element
{'a': 1, 'b': MISSING}               -- Becomes: {'a': 1} (b omitted)
MISSING + 5                          -- Returns: MISSING
----

==== NULL vs. MISSING

*Key Differences:*

[cols="2,3,3", options="header"]
|===
|Aspect |NULL |MISSING

|Origin
|Explicit null in data
|Absent/non-existent data

|In Tuples
|Can be attribute value
|Causes attribute to be omitted

|In Arrays/Bags
|Valid element
|Valid element

|Equality
|NULL = NULL is NULL (SQL) / eqg(NULL, NULL) is TRUE (grouping)
|MISSING = MISSING is MISSING / eqg(MISSING, MISSING) is TRUE (grouping)

|Grouping
|NULLs group together
|MISSINGs group with NULLs (coerced to NULL)

|Path Result
|Explicit null value stored
|Navigation to non-existent path
|===

*Examples:*
[source, partiql]
----
-- Distinction preserved
{'a': NULL}                          -- Has 'a' attribute with NULL value
{'b': 1}                             -- Lacks 'a' attribute (MISSING)

-- Both in array
[NULL, MISSING, 1]                   -- Array with both absent types

-- Grouping behavior
SELECT g 
FROM [{'x': NULL}, {'x': MISSING}, {}] AS t
GROUP BY t.x GROUP AS g
-- Results in one group: both NULL and MISSING group together
----
